1. アーキテクチャ概要

1.1 レイヤー構成

Tauri 2 のデスクトップアプリケーションとして、フロントエンド（React/TypeScript）と バックエンド（Rust）を Tauri IPC ブリッジで接続する2層構成。 

┌────────────────────────────────────────────────────────────┐
│  フロントエンド（Webビュー）                                │
│                                                            │
│  App.tsx                                                   │
│  ├─ useAppState（状態管理フック）                          │
│  ├─ FileInputSection コンポーネント × 2                    │
│  ├─ MappingTable コンポーネント                            │
│  └─ ProgressBar コンポーネント                             │
│                                                            │
│  api/tauri.ts（Tauriコマンド呼び出しの窓口）               │
└─────────────────────────┬──────────────────────────────────┘
                          │ Tauri IPC（invoke / event）
┌─────────────────────────▼──────────────────────────────────┐
│  バックエンド（Rustバイナリ）                               │
│                                                            │
│  commands.rs（コマンドハンドラ・バリデーション）            │
│  ├─ csv_reader.rs（CSVファイル読み込み・文字コード変換）    │
│  ├─ comparison.rs（突合処理コアロジック）                  │
│  └─ config.rs（設定ファイル保存・読み込み）                │
└────────────────────────────────────────────────────────────┘

1.2 通信方式

方向方式用途
フロント → バック Tauri invoke（同期的なコマンド呼び出し） CSV読み込み、突合実行、設定保存・読み込み
バック → フロント Tauri イベント（emit / listen） 突合処理中の進捗通知（comparison-progress イベント）

2. フロントエンド設計

2.1 コンポーネント構成

コンポーネントファイル役割
App src/App.tsx メイン画面レイアウト。useAppState フックからすべての状態とハンドラを取得し、 各セクションへ Props として渡す。
FileInputSection src/components/FileInputSection.tsx ファイルパス入力・文字コード選択・参照ボタンをまとめたUI部品。 MJSシステム・他社システムの2箇所で共用する。
MappingTable src/components/MappingTable.tsx 突合設定テーブル。4行（比較対象・MJSシステム・他社システム・許容誤差）× 列数（MJSのヘッダー数）の構成。 CSVが未取込の場合はガイドメッセージを表示する。
ProgressBar src/components/ProgressBar.tsx 突合実行中のみ表示される進捗バー。 バックエンドから受信した step / total を元に幅を計算する。

FileInputSection Props

Prop型説明

onEncodingChange(enc: Encoding) => void文字コード変更時のコールバック

Prop型説明

2.2 状態管理

すべてのアプリ状態を src/hooks/useAppState.ts の useAppState カスタムフックで一元管理する。 React の useState と useCallback を使い、状態とその更新関数を一つのフックにまとめる。

AppState の構造

フィールド型説明
mjsPathstringMJSシステムCSVのファイルパス
mjsEncodingEncodingMJSシステムCSVの文字コード
otherPathstring他社システムCSVのファイルパス
otherEncodingEncoding他社システムCSVの文字コード
mjsHeadersstring[] | null取り込んだMJSのヘッダー（未取込はnull）
otherHeadersstring[] | null取り込んだ他社システムのヘッダー（未取込はnull）
columnsColumnMapping[]突合設定列の配列
outputDirstring出力フォルダパス
isRunningboolean突合処理の実行中フラグ
progressProgressPayload | null最新の進捗情報
errorstring | nullエラーメッセージ（なければnull）

フック内部のヘルパー関数

関数説明
buildColumns(mjsHeaders, otherHeaders) MJSヘッダーを元に初期の ColumnMapping[] を生成する。 他社ヘッダーと名称が完全一致する場合は otherHeader を自動設定。 先頭列（index=0）は isCompare: false に固定する。
makeTimestamp() 実行時の yyyymmddhhmm 形式タイムスタンプ文字列を生成する。
buildHeaderMismatchError(configHeaders, csvHeaders) 設定ファイルのヘッダーと現在のCSVヘッダーを比較し、不一致があれば 差分を列挙したエラーメッセージを返す。一致している場合は null を返す。

ファイル：src/types/index.ts

3. バックエンド設計

3.1 モジュール構成

ファイル役割
lib.rsTauriアプリの初期化。プラグイン登録とコマンドハンドラの登録を行う
main.rsエントリーポイント。lib::run() を呼ぶだけ
types.rsフロントエンドと共有する構造体の定義（serde による JSON シリアライズ対応）
commands.rsTauriコマンドハンドラと実行前バリデーション
csv_reader.rsCSVファイルの読み込み・文字コード変換・ヘッダー解析
comparison.rs突合処理のコアアルゴリズムと出力CSV生成
config.rs突合設定のJSON保存・読み込み

3.2 型定義（types.rs）

構造体説明serde
ColumnMapping突合設定の1列分camelCase, Serialize/Deserialize/Clone
ComparisonConfig突合実行設定全体（パス・文字コード・列設定・タイムスタンプ）camelCase, Serialize/Deserialize
SummaryRowサマリーCSVの1行分（item_name / result）camelCase, Serialize/Deserialize
ComparisonResult突合処理の結果（summary / summary_file / detail_file）camelCase, Serialize/Deserialize
ConfigData設定ファイルの構造（columns のみ）camelCase, Serialize/Deserialize/Clone
ProgressPayload進捗イベントのペイロード（message / step / total）camelCase, Serialize/Clone

Rustのフィールド名はスネークケース（例：mjs_header）だが、 #[serde(rename_all = "camelCase")] によりJSON上はキャメルケース（例：mjsHeader）に変換される。 これによりフロントエンドのTypeScript型定義と自然に対応する。

3.3 コマンドハンドラ（commands.rs）

コマンド種別説明
load_csv 同期 パスと文字コードを受け取り、CSVのヘッダー行を返す
execute_comparison 非同期 validate_config でバリデーション後、 tokio::task::spawn_blocking でブロッキングスレッドに突合処理を委譲する。 処理中は comparison-progress イベントを emit して進捗を通知する。
save_config 同期 突合設定をJSONファイルに保存する
load_config 同期 JSONファイルから突合設定を読み込む

validate_config のチェック項目

  1. MJSシステムのCSVパスが空でない
  2. 他社システムのCSVパスが空でない
  3. 出力フォルダパスが空でない
  4. columns が空でない（ファイル取込済みであること）
  5. 先頭列（キー列）の other_header が選択済み
  6. 比較対象列（is_compare = true）が1件以上存在する
  7. 比較対象列すべての other_header が選択済み

3.4 突合処理ロジック（comparison.rs）

内部型

型説明
ColInfo比較列1件の情報（ColumnMapping参照 + MJSのCSVインデックス + 他社のCSVインデックス）
DetailRow明細CSV1行分のデータ（key / mjs_val / other_val / diff）
ComparisonStats比較ループの集計結果（不一致件数配列 / 明細行配列 / 片側のみカウント）

run() の処理フロー

  1. MJSシステムCSVを読み込む（on_progress: 1/6）
  2. 他社システムCSVを読み込む（on_progress: 2/6）
  3. キー列・比較列のCSVインデックスを解決する（on_progress: 3/6）
  4. build_mjs_index でMJSレコードをHashMapに格納する
  5. compare_records で他社レコードと突合する
  6. サマリーCSVを生成する（on_progress: 4/6）
  7. 明細CSVを生成する（on_progress: 5/6）
  8. ファイルを出力する（on_progress: 6/6）

compare_records() の処理

  1. 他社CSVの全レコードを1行ずつ処理する：
    • キー値でMJSのHashMapを検索する
    • マッチした場合：各比較列を values_match で突合し、不一致なら DetailRow を追加する
    • マッチしない場合：other_only_count をインクリメントし、全比較列に他社値のみの DetailRow を追加する
  2. MJSレコードのうち他社CSVにマッチしなかったものを検出する（mjs_only）：
    • mjs_only_count をインクリメントし、全比較列にMJS値のみの DetailRow を追加する

values_match() の判定ロジック

条件判定方法
tolerance = 0文字列として完全一致（mjs_val == other_val）
tolerance > 0、両方 f64 変換可能絶対差 ≤ tolerance
tolerance > 0、どちらか変換不可文字列として完全一致（フォールバック）

ファイル出力

  • 文字コード：UTF-8 BOM付き（ExcelでCSVを直接開けるようにするため BOM = EF BB BF を先頭に付与）
  • 明細CSVが空（不一致が一件もない）の場合は明細ファイルを生成しない

3.5 CSV読み込み処理（csv_reader.rs）

公開関数

関数説明
read_headers(path, encoding)ヘッダー行のみを返す（ファイル取込時に使用）
read_records(path, encoding)ヘッダーと全データ行を返す（突合実行時に使用）

内部ヘルパー関数

関数説明
read_as_text(path, encoding)ファイルを読み込み、指定文字コードでデコードしてテキストを返す
make_csv_reader(text)テキストから csv::Reader を構築する
collect_csv_headers(reader)Reader からヘッダーを収集し、空チェックを行う
decode_bytes(bytes, encoding)encoding_rs クレートを使って SJIS または UTF-8 にデコードする。BOM は除去する

対応文字コード

指定値処理
sjisSHIFT_JIS でデコード
utf-8UTF-8 でデコード
utf-8-bomUTF-8 でデコード（BOM は trim_start_matches で除去）

関数説明

4. データフロー

4.1 ファイル取込フロー

[ユーザー] ファイルパスを入力して「ファイル取込」をクリック
     ↓
[useAppState::loadFiles]
  Promise.all で MJS・他社 の load_csv を並列実行
     ↓
[Rust: commands::load_csv]
  csv_reader::read_headers(path, encoding)
    → read_as_text でバイト読み込み＆デコード
    → make_csv_reader → collect_csv_headers
  → Vec<String> (ヘッダーリスト) を返す
     ↓
[useAppState]
  mjsHeaders / otherHeaders を更新
  buildColumns() で ColumnMapping[] を生成
  columns を更新 → MappingTable が再描画される

4.2 突合実行フロー

[ユーザー]「実行」をクリック
     ↓
[useAppState::execute]
  isRunning = true
  comparison-progress イベントの listen を開始
  api.executeComparison(config) を呼び出す
     ↓
[Rust: commands::execute_comparison]
  validate_config でバリデーション
  tokio::spawn_blocking で comparison::run() を実行
     ↓
[Rust: comparison::run]
  Step1: MJS CSV を read_records で読み込み → emit progress(1/6)
  Step2: 他社 CSV を read_records で読み込み → emit progress(2/6)
  Step3: インデックス解決・build_mjs_index → emit progress(3/6)
  Step4: compare_records で突合ループ
         不一致・片側のみを集計
  Step5: build_summary_csv → emit progress(4/6)
  Step6: build_detail_csv → emit progress(5/6)
  Step7: write_bom_csv でファイル出力 → emit progress(6/6)
  → ComparisonResult を返す
     ↓
[Tauri イベント: comparison-progress]
  フロントエンドの listen コールバック → progress 状態を更新
  → ProgressBar が再描画される
     ↓
[useAppState::execute (finally)]
  unlisten でイベントリスナーを解除
  isRunning = false
  api.showCompletionDialog() で完了ダイアログを表示

4.3 設定保存・読み込みフロー

【保存】
[ユーザー]「設定出力」をクリック
  → pickJsonFileForSave() でファイル保存ダイアログ
  → api.saveConfig(path, { columns }) を呼び出す
  → Rust: config::save() が JSON に書き出す

【読み込み】
[ユーザー]「設定取込」をクリック
  → pickJsonFileForOpen() でファイル選択ダイアログ
  → api.loadConfig(path) を呼び出す
  → Rust: config::load() が JSON を読み込み ConfigData を返す
  → buildHeaderMismatchError() でヘッダー不一致チェック
      不一致あり → エラー表示して中断
      一致 → state.columns を更新 → MappingTable が再描画される
