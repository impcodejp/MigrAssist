1. 概要

1.1 目的

給与・勤怠システム導入時に、現行システム（他社システム）と新システム（MJSシステム）がそれぞれ出力した CSVファイルを読み込み、指定した項目同士を1レコードずつ突合して差異を検出するデスクトップツール。

1.2 技術スタック

区分技術
フレームワークTauri 2
フロントエンドReact 19 + TypeScript 5
バックエンドRust
ビルドツールVite 7

1.3 対応OS

Windows 11

3. 機能仕様

3.1 ファイル入力エリア

3.1.1 MJSシステム CSVファイル

項目仕様
入力方式テキストボックスへの直接入力、または「参照」ボタンによるファイル選択ダイアログ
文字コード選択ドロップダウン（選択肢：sjis / utf-8 / utf-8-bom）
デフォルト文字コードsjis
ファイル形式CSV（.csv）

3.1.2 他社システム CSVファイル

MJSシステムと同様の仕様。

3.1.3 「ファイル取込」ボタン

  • 両ファイルのパスが入力済みであることを検証する
  • 各ファイルを指定文字コードで読み込み、ヘッダー行を解析する
  • 取込成功後、突合設定テーブルを更新する
  • エラー時はエラー表示エリアにメッセージを表示する

エラーケース：

  • ファイルパスが未入力
  • ファイルが存在しない
  • 指定文字コードで読み込めない
  • ヘッダー行が空

3.2 突合設定テーブル

ファイル取込後に表示されるインタラクティブなテーブル。突合する列の対応関係を定義する。

3.2.1 テーブル構造

行名 キー列（先頭） 比較列（2列目以降）
比較対象 — （固定・変更不可） チェックボックス（ON/OFF）
MJSシステム MJSの1列目ヘッダー名（読み取り専用） MJSのヘッダー名（読み取り専用）
他社システム プルダウン（必須選択） プルダウン（比較対象ONの場合は必須）
許容誤差± （なし） 整数入力（空欄 = 0）

3.2.2 行の定義

行名内容
比較対象 チェックボックス。ONの列を突合対象にする。キー列（先頭列）は比較対象外（— 固定）
MJSシステム 取り込んだMJSシステムCSVのヘッダー名をそのまま表示（読み取り専用）
他社システム プルダウン。他社システムCSVのヘッダー一覧から選択。MJSと名称が完全一致する場合は初期値として自動選択される
許容誤差± 数値入力フィールド（整数）。空欄は 0 として扱う。数値型の列にのみ有効

3.2.3 列構成ルール

  • 先頭列（キー列）：MJSシステムCSVの1列目を突合キーとして固定で使用する。比較対象チェックは常にOFF・変更不可
  • 2列目以降（比較列）：突合して差異を検出する列。ファイル取込時にMJSシステムCSVのヘッダーに従って自動生成される。列の追加・削除は不可

3.2.4 初期値自動マッチング

ファイル取込後、他社システム行のプルダウンを以下のロジックで初期設定する：

  1. MJSシステムのヘッダー名と他社システムのヘッダー名を完全一致で比較
  2. 一致した場合 → 対応する他社システムのヘッダーを初期値にセット
  3. 一致しない場合 → プルダウンは未選択（空白）

3.3 設定の保存・読み込み

3.3.1 「設定出力」ボタン

現在の突合設定テーブルの状態をJSONファイルに保存する。

保存対象：

  • MJSシステム側の各列ヘッダー名
  • 他社システム側の対応列ヘッダー名
  • 比較対象チェックの状態
  • 許容誤差値

ファイル形式：JSON（デフォルトファイル名：mapping-config.json）

3.3.2 「設定取込」ボタン

保存済みの設定ファイルを読み込み、突合設定テーブルを復元する。

読み込んだ設定のヘッダー名と現在取り込み済みCSVのヘッダーが不一致の場合は、どのヘッダーが異なるかを明示したエラーメッセージを表示し、設定の適用を中断する。

3.4 出力フォルダ

項目仕様
入力方式テキストボックスへの直接入力、または「参照」ボタンによるフォルダ選択ダイアログ
用途比較結果ファイル（サマリー・明細）の出力先

3.5 実行ボタン

3.5.1 事前バリデーション

以下をすべて満たさない場合はエラーメッセージを表示して処理を中断する：

  1. MJS・他社システムのCSVがファイル取込済み
  2. キー列の他社システム側プルダウンが選択済み
  3. 比較対象チェックがONの列が1件以上存在する
  4. 比較対象ONの列すべてで他社システム側プルダウンが選択済み
  5. 出力フォルダが指定済み

3.5.2 突合処理ロジック

  1. MJSシステムCSVをキー列の値をキーとしてHashMapに格納
  2. 他社システムCSVを1行ずつ読み込む
  3. 他社システムのキー列の値でHashMapを検索
    • 一致レコードあり → 各比較列を突合
    • 一致レコードなし → 「他社側のみ存在」として記録
  4. MJS側にしか存在しないレコードを「MJS側のみ存在」として記録
  5. 比較列ごとの差異チェック：
    • 許容誤差が0のとき：文字列として完全一致チェック
    • 許容誤差がN（>0）のとき：数値変換後に絶対差 ≤ N で一致とみなす
    • どちらか一方が数値変換できない場合：文字列一致へフォールバック
  6. 結果をCSVに出力

3.5.3 進捗表示

実行中は画面下部に進捗バーを表示する。処理ステップ単位で更新される。

ステップメッセージ
1/6MJSシステムCSVを読み込み中...
2/6他社システムCSVを読み込み中...
3/6突合処理中...
4/6サマリーファイルを生成中...
5/6明細ファイルを生成中...
6/6完了

3.6 出力ファイル仕様

出力フォルダに以下の2ファイルを生成する。ファイル名のタイムスタンプは実行日時（ローカル時刻）。

文字コード：UTF-8 BOM付き（Excelで直接開けるようにするため）

3.6.1 サマリー比較_yyyymmddhhmm.csv

比較列ごとに1行、全体集計を出力する。

列名内容
項目名MJSシステム側のヘッダー名
結果不一致件数が0件の場合 〇、1件以上の場合は不一致件数（数値）

末尾に片側のみ存在レコードの集計行を追加する：

行内容
MJS側のみ存在MJSにのみ存在するレコード件数
他社側のみ存在他社システムにのみ存在するレコード件数

出力例：

項目名,結果
出勤日数,〇
欠勤日数,3
出勤時間,〇
所定内残業,12
MJS側のみ存在,2
他社側のみ存在,0

3.6.2 明細比較_yyyymmddhhmm.csv

不一致があった比較列ごとにセクションを分けて出力する。不一致が0件の列はスキップする。

各セクションの構造：

  • セクションヘッダー行：項目名：<ヘッダー名>
  • 列ヘッダー行：社員コード,MJS値,他社値,差異（キー列のヘッダー名を使用）
  • データ行：不一致レコード1件につき1行
列名内容
キー値（MJS1列目のヘッダー名）突合キーの値
MJS値MJSシステム側の該当列の値
他社値他社システム側の該当列の値
差異MJS値 − 他社値（数値列のみ。文字列列は空欄）

片側のみ存在レコードも全比較列に出力する（存在しない側の値は空欄）。

許容誤差内の差異は「一致」とみなすため出力しない。

出力例：

項目名：欠勤日数
社員コード,MJS値,他社値,差異
1001,2,0,2
1045,1,3,-2

項目名：所定内残業
社員コード,MJS値,他社値,差異
1001,20,25,-5
